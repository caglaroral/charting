ChartScript

Write your own indicators in plain JavaScript with a Pine Script-like API. They are stored per user, drawn on the chart like built-in indicators and can drive server-side alerts.

  • The same runtime draws the indicator in your browser and evaluates alerts on the server, so an alert always sees the values you see on the chart.
  • Code runs isolated: in the browser inside a sandboxed iframe + Web Worker without network access, on the server in an unprivileged sandbox. A bug or an endless loop cannot break the app.
  • Anything JavaScript offers is available: const/let, loops, functions, objects, Math.

Quick start

Open Editor in the top toolbar, press + New and you get this template:

// ChartScript: JavaScript with a Pine-like API. Series are arrays aligned to bars.
indicator('My Indicator', { overlay: true })

const fast = input('Fast MA', 9)
const slow = input('Slow MA', 21)
const source = input.source('Source', 'close')

const f = ta.ema(source, fast)
const s = ta.ema(source, slow)

plot(f, { title: 'Fast', color: '#2962ff' })
plot(s, { title: 'Slow', color: '#ff6d00', width: 2 })

plotshape(ta.crossover(f, s), { title: 'Buy', location: 'belowbar', color: '#26a69a', shape: 'triangleup', text: 'BUY' })
plotshape(ta.crossunder(f, s), { title: 'Sell', location: 'abovebar', color: '#ef5350', shape: 'triangledown', text: 'SELL' })

Press ▶ Run to test it against the current chart, then Save & add to chart.

Core concepts

Series are arrays

A series is a plain JavaScript array with one element per bar, oldest first. close[0] is the oldest loaded bar, close[n - 1] the newest (the forming bar). All series have the same length n.

This is the opposite of Pine, where close[1] means "one bar ago". In ChartScript use shift(close, 1) for a whole series, or close[i - 1] inside a loop.

na / null

Missing values are null (Pine na). Moving averages return null until they have enough bars; functions propagate null. Use na(x) to test and nz(x, y) to replace.

JavaScript treats null as 0 in comparisons: null < 5 is true. Where Pine's na comparison would be false, guard explicitly: a != null && b != null && a > b.

Vectorized vs bar by bar

Most functions take and return whole series. Operators like + do not work on arrays, so use the helpers or compute bar by bar:

Vectorized
const mid = div(add(high, low), 2)
const spread = sub(ta.ema(close, 12), ta.ema(close, 26))
Bar by bar
const mid = series(i => (high[i] + low[i]) / 2)
const up = series(i => close[i] > open[i] ? 1 : 0)

series(f) calls f(i) for i = 0 … n-1 in order and returns an array; undefined/NaN become null. A plain for loop that fills an array works just as well.

State (Pine var)

Because the loop runs from the oldest to the newest bar, a variable declared outside it keeps its value between bars, exactly like Pine's var:

// Count consecutive up closes (Pine: var int streak = 0)
let streak = 0
const streaks = series(i => {
  if (i > 0 && close[i] > close[i - 1]) streak++
  else streak = 0
  return streak
})
plot(streaks, { title: 'Up streak', style: 'histogram', color: '#26a69a' })

Other timeframes: security()

// 4-hour 21 SMA on any chart timeframe
const ma4h = security('4h', s => s.ta.sma(s.close, 21))
// several values at once
const d = security('D', s => s.close)

security(tf, s => expr) evaluates expr on bars of another timeframe and maps the result back onto chart bars. s has the same API as the main script (s.open … s.ohlc4, s.ta, s.series, s.shift, helpers).

  • Timeframes: app ids ('15m', '4h', '1D', '1W') or Pine ids ('15', '240', 'D', 'W', 'M').
  • No lookahead (Pine barmerge.lookahead_off): a higher-timeframe value appears on the chart once its bar has closed; until then the previous one is shown. This avoids repainting. Opt in with security(tf, fn, { lookahead: true }).
  • The data is loaded on demand (exchange first, older history from ClickHouse), so the first run on a new symbol can take a moment.
  • Indexing x[i - 1] on a security result refers to the previous chart bar, as in Pine.

Alerts on custom indicators

In the indicator's legend open … → Add alert…. You can alert on:

  • any plot compared with a value or with another plot (crossing, crossing up/down, greater/less than),
  • any plotshape() signal: the alert fires when the shape appears.

Alerts are evaluated by the server with the same code and your saved input values, also while the browser is closed, and delivered via the channels you chose (in-app, Telegram, e-mail, webhook). Custom indicator alerts require a plan that includes them.

Alerts reference plots and shapes by their title. Renaming a plot after creating an alert breaks the alert — keep titles stable.

indicator('Trend', { overlay: true })
const len = input('Length', 50)
const ma = ta.ema(close, len)
const up = series(i => i > 0 && ma[i - 1] != null &&

Bollinger Bands with a squeeze highlight

indicator('BB squeeze', { overlay: true })
const len = input('Length', 20)
const mult = input('StdDev', 2)
const bb = ta.bb(close, len, mult)
const width = div(sub(bb.upper, bb.lower), bb.basis)
const tight = series(i => width[i] != null && width[i] <= ta.lowest(width, 120)[i] * 1.1)

plot(bb.upper, { title: 'Upper', color: '#2962ff' })
plot(bb.basis, { title: 'Basis', color: '#ff6d00' })
plot(bb.lower, { title: 'Lower', color: '#2962ff' })
fill(bb.upper, bb.lower, { color: i => tight[i] ? color.new(color.yellow, 80) : color.new('#2962ff', 92) })
Calling ta.lowest(width, 120) inside series() recomputes it for every bar. Compute it once outside the loop for speed: const low120 = ta.lowest(width, 120), then use low120[i].

Multi-timeframe trend filter

indicator('HTF trend', { overlay: true })
const tf = input.select('Higher timeframe', '4h', ['1h', '4h', '1D', '1W'])
const len = input('Length', 50)
const htf = security(tf, s => s.ta.ema(s.close, len))
const bull = series(i => htf[i] != null && close[i] > htf[i])

plot(htf, { title: 'HTF EMA', width: 2, style: 'stepline', color: i => bull[i] ? color.teal : color.red })
fill(close, htf, { color: i => bull[i] ? color.new(color.teal, 88) : color.new(color.red, 88) })

Stateful trailing stop

indicator('ATR trailing stop', { overlay: true })
const mult = input('ATR multiplier', 3)
const atr = ta.atr(14)
let stop = null, long = true
const out = series(i => {
  if (atr[i] == null) return null
  const longStop = close[i] - mult * atr[i], shortStop = close[i] + mult * atr[i]
  if (stop == null) stop = longStop
  if (long) { stop = Math.max(stop, longStop); if (close[i] < stop) { long = false; stop = shortStop } }
  else { stop = Math.min(stop, shortStop); if (close[i] > stop) { long = true; stop = longStop } }
  return stop
})
plot(out, { title: 'Stop', style: 'circles', width: 2, color: i => close[i] > out[i] ? color.lime : color.red })

Limits & sandbox

LimitValue
Run time3 s per run in the browser; 10 s per request on the server. Longer runs are stopped (endless loops included).
Network, DOM, cookiesnot available — fetch, XMLHttpRequest, document, localStorage do not exist or are blocked
Dataonly the bars passed to the script (chart bars and security() timeframes)
Number of scripts / indicatorsdepends on your plan (see the plan limits in the user menu)

In the browser your code runs in a Web Worker inside a sandboxed iframe with a content security policy that blocks all network access. On the server it runs in a fresh JavaScript context in an unprivileged process without network access. Results are plain data; the code never touches the application.

Troubleshooting

SymptomCause / fix
Nothing drawn, no errorDid you call plot()? Values may all be null (length longer than the loaded history, or a missing null guard).
Line goes to zero at the startnz() or a null treated as 0 — return null while there is not enough data.
x is not definedtypo, or a Pine name without a ChartScript equivalent (e.g. syminfo, strategy.*).
Cannot read properties of undefinedindexing outside the array: check i - k >= 0 before x[i - k].
Execution timed outan endless loop, or heavy work inside series() (see the BB example note).
Signals differ from TradingViewcheck x[1] vs x[i - 1], na comparisons, and that security() uses no lookahead (TradingView default).
Alert does not fireplot/shape titles changed after the alert was created, or the plan does not include custom indicator alerts.
